## 1. الصورة الكبيرة: موقع بلا خادم يتكلم مع الذكاء الاصطناعي

«يونس» **موقع ثابت (static site)**: ملفات HTML وCSS وJavaScript فقط، تُنشر على GitHub Pages مجاناً. لا يوجد خادم (backend) ولا قاعدة بيانات.

```
متصفح الطالب ──(ملفات الموقع)──> GitHub Pages
      │
      ├── localStorage   ← خطته وبطاقاته وتقدّمه (على جهازه فقط)
      ├── data/*.json     ← بيانات الجامعات (ملفات ثابتة من الموقع نفسه)
      └──(HTTPS)──> api.anthropic.com   ← فقط عند طلب ميزة ذكاء اصطناعي، بمفتاح الطالب
```

**لماذا هذا التصميم؟**
- **مجاني بالكامل**: لا تدفع ثمن خادم.
- **آمن**: لا قاعدة بيانات يمكن اختراقها، ولا كلمات مرور مخزّنة.
- **خصوصية**: بيانات الطالب لا تغادر جهازه.

**المقابل (trade-off):** ميزات الذكاء الاصطناعي تحتاج مفتاح Claude API من الطالب نفسه (BYOK: Bring Your Own Key)، لأن أي مفتاح نضعه في كود الموقع سيراه الجميع. إذا أردت لاحقاً أن يعمل الذكاء الاصطناعي للجميع بلا مفتاح، تحتاج **خادماً وسيطاً صغيراً** (مثل Cloudflare Worker) يحمل مفتاحك ويضع حداً للاستهلاك لكل طالب. هذه هي الخطوة التي تحوّل المشروع إلى منتج SaaS حقيقي.

**كيف يتكلم الموقع مع Claude؟** عبر **حزمة Anthropic الرسمية (SDK)** المحفوظة داخل الموقع (`docs/vendor/anthropic.min.js`). كل الطلبات تمر بدالة واحدة في `src/77-ai.js`:

```js
function params(input,opts,extra){
  var p={
    model:"claude-opus-5-5", max_tokens:opts.maxTokens||64000,
    output_config:{effort:opts.effort||"medium"},          // عمق التفكير: low / medium / high
    betas:["server-side-fallback-2026-07-01"], fallbacks:"default",
    messages:toMsgs(input)
  };
  if(opts.system) p.system=opts.system;                    // تعليمات ثابتة لكل ميزة
  return Object.assign(p,extra||{});
}
```

- **`model`**: أقوى نموذج متاح اليوم، Claude Opus 5.5.
- **`effort`**: نختار `high` للحل والتصحيح (يحتاج تفكيراً عميقاً)، و`medium` للترجمة واستخراج النص (سرعة مع جودة).
- **`system`**: «تعليمات النظام»، وهي التي تحدد شخصية يونس وقواعد الدقة لكل ميزة.
- **`stream`**: نستقبل الإجابة كلمة بكلمة (streaming) فيراها الطالب فوراً بدل الانتظار.

## 2. عدسة يونس: الكاميرا وتحليل الصور

**الملف:** `src/71-lens.js`

### 2.1 تشغيل الكاميرا: `getUserMedia`

```js
navigator.mediaDevices.getUserMedia({audio:false, video:{facingMode:{ideal:"environment"}, width:{ideal:3840}, height:{ideal:2160}}})
  .then(function(stream){ video.srcObject=stream; video.play() })
```

- `facingMode: "environment"` تعني الكاميرا الخلفية في الجوال (الأفضل لتصوير الأوراق). زر «بدّل الكاميرا» يحوّلها إلى `user` (الأمامية).
- نطلب دقة **4K** (`ideal`)، والمتصفح يعطي أعلى دقة يدعمها الجهاز.
- **الأذونات:** المتصفح يسأل الطالب أولاً، ولا تعمل الكاميرا إلا على HTTPS. لذلك نتعامل مع كل خطأ برسالة واضحة: `NotAllowedError` (رفض الإذن)، و`NotFoundError` (لا توجد كاميرا).
- **احترام الخصوصية:** نوقف الكاميرا فور مغادرة الصفحة أو إخفاء التبويب:

```js
function camStop(){ if(camStream){ camStream.getTracks().forEach(function(t){t.stop()}); camStream=null } }
document.addEventListener("visibilitychange",function(){ if(document.hidden) camStop() });
```

**الالتقاط:** نرسم إطار الفيديو الحالي على `<canvas>`:

```js
var c=document.createElement("canvas"); c.width=video.videoWidth; c.height=video.videoHeight;
c.getContext("2d").drawImage(video,0,0);
```

### 2.2 لماذا نصغّر الصورة؟ وإلى أي حجم بالضبط؟

صورة الجوال قد تكون 12 ميغابكسل (4000×3000). Claude Opus 5.5 يقرأ الصور حتى **2576 بكسل في الضلع الأطول** و**3.75 ميغابكسل** إجمالاً. أي شيء أكبر يُصغَّر على الخادم ويضيّع وقت الرفع. لذلك نصغّرها نحن **إلى هذا الحد تماماً**، فيبقى النص حاداً ولا نهدر شيئاً:

```js
var s=Math.min(1, IMG_EDGE/Math.max(w,h), Math.sqrt(IMG_PIXELS/(w*h)));   // IMG_EDGE=2576, IMG_PIXELS=3.75e6
```

- `IMG_EDGE/Math.max(w,h)`: نسبة التصغير حتى لا يتجاوز الضلع الأطول 2576.
- `Math.sqrt(IMG_PIXELS/(w*h))`: نسبة التصغير حتى لا تتجاوز المساحة 3.75 ميغابكسل. نستخدم الجذر لأن المساحة = العرض × الارتفاع.
- نأخذ **الأصغر** بين النسبتين (والرقم 1 حتى لا نكبّر صورة صغيرة).

ثم نحوّلها إلى **JPEG بجودة 92%** ونصّ **base64** (الصيغة التي يقبلها الـ API)، ونخفض الجودة تدريجياً إذا تجاوزت 5 ميغابايت:

```js
var q=0.92, url=c.toDataURL("image/jpeg",q);
while(url.length>IMG_B64_MAX && q>0.5){ q-=0.1; url=c.toDataURL("image/jpeg",q) }
```

**التدوير:** نرسم الصورة على canvas مدوَّر بزاوية 90 درجة (`ctx.rotate`)، ونبدّل العرض بالارتفاع. الصور المقلوبة تقلل دقة القراءة كثيراً.

### 2.3 الرسالة المتعددة الوسائط (multimodal)

نرسل الصور **قبل** النص، لأن Claude يفهم السؤال أفضل بعد أن «يرى» الصورة:

```js
var content=lensImgs.map(function(m){
  return {type:"image", source:{type:"base64", media_type:"image/jpeg", data:m.fit.data}};
});
content.push({type:"text", text: task + "\n\nThe student's exact request: " + ask});
sample([{role:"user", content:content}], {system:lensSystem(), effort:"high", onText:...});
```

### 2.4 سرّ الدقة: تعليمات النظام

الدقة لا تأتي من النموذج وحده، بل من **هندسة التعليمات (prompt engineering)**. هذه قواعدنا:

```
- Read the whole image carefully first. Quote the exact numbers, symbols, units and wording you rely on.
- If a part is blurry, cut off or ambiguous, say exactly which part and what you assumed. Never invent content.
- For any calculation, work step by step, then check the result by substituting back or by a second method.
- Do exactly what the student asked...
```

- **«اقتبس الأرقام التي تعتمد عليها»** يجبر النموذج على القراءة الدقيقة قبل الحل.
- **«لا تخترع، وقل ما الذي لم تستطع قراءته»** يمنع الهلوسة (hallucination).
- **«تحقق من النتيجة بطريقة ثانية»** يكشف الأخطاء الحسابية.
- **سبعة أوضاع** لكل منها تعليمة خاصة: حل، شرح، استخراج نص حرفي (OCR)، تلخيص، بطاقات، تصحيح حل الطالب، سؤال حر.

### 2.5 البث المباشر (streaming) بلا تقطيع

كل كلمة جديدة تصل تعيد رسم الإجابة. لو رسمنا 50 مرة في الثانية لتباطأ الجوال، فنستخدم `requestAnimationFrame` لنرسم مرة واحدة لكل إطار شاشة:

```js
if(lensFrame) return;
lensFrame=requestAnimationFrame(function(){ lensFrame=0; $("lensOut").innerHTML=renderMd(lensText) });
```

### 2.6 من الصورة إلى بطاقات المراجعة

في وضع «حوّلها إلى بطاقات» نطلب **JSON** فقط: `{"cards":[{"q":"...","a":"..."}]}`، ثم نعرضها مع مربعات اختيار، ونضيف المختار إلى نظام المراجعة المتباعدة الموجود أصلاً. هكذا تتكامل الميزات بدل أن تكون جزراً منفصلة.

> **جرّب بنفسك:** صوّر مسألة من كتابك، واختر «حلّ المسألة»، ثم «صحّح حلّي» على حلّك المكتوب بخط يدك.
>
> **تمرين:** أضف أداة **قصّ (crop)**: يسحب الطالب مستطيلاً على الصورة، وترسم أنت ذلك الجزء فقط على canvas جديد. القصّ يزيد الدقة لأن النموذج يركّز على السؤال المطلوب.

## 3. ترجمة الملفات والصور

**الملف:** `src/72-translate.js`

### 3.1 قراءة أي ملف داخل المتصفح

| النوع | الأداة | الفكرة |
|---|---|---|
| PDF | **pdf.js** (من Mozilla) | يقرأ «طبقة النص» صفحة صفحة |
| Word / PowerPoint / Excel | **JSZip** | ملف `.docx` هو في الحقيقة **ملف ZIP** فيه ملفات XML! نفكّه ونقرأ `word/document.xml` |
| صورة | canvas | تُرسل كصورة |

جرّب: غيّر امتداد أي ملف Word إلى `.zip` وافتحه، سترى بنيته.

### 3.2 الملفات المصوّرة (scanned)

بعض ملفات PDF صور ممسوحة بلا نص. نكتشفها بعدّ الحروف: إذا كان متوسط الحروف أقل من 30 في الصفحة، نحوّل كل صفحة إلى صورة ونترجمها كصورة:

```js
if(chars < 30*doc.numPages){ trSrc={kind:"pages", images: await pdfPagesAsImages(doc, 40)} }
```

`pdfPagesAsImages` ترسم كل صفحة على canvas بدقة نحو 2000 بكسل (`page.render`)، ثم نعيد استخدام دالة التصغير نفسها من العدسة (`fitImage`). **إعادة استخدام الكود (reuse)** مبدأ أساسي في الهندسة.

### 3.3 لماذا نقسّم النص إلى أجزاء (chunking)؟

1. **كتاب من 100 صفحة** أطول من أن نترجمه في رد واحد.
2. **التقدّم المرئي:** يرى الطالب «الجزء 3 من 12».
3. **المتانة:** إذا انقطع الإنترنت يبقى ما تُرجم.

نقسّم عند **حدود الفقرات** (ثم الجمل) حتى لا نقطع جملة في منتصفها، بحجم نحو 5000 حرف. ولتبقى المصطلحات متسقة بين الأجزاء، نرسل آخر 600 حرف من الترجمة السابقة كسياق:

```
This is part 3 of 12 of one document.
The end of the previous part, already translated (for consistent terms only, do not repeat it):
<previous> ... </previous>
Translate:
<document_part> ... </document_part>
```

وسوم XML مثل `<document_part>` تفصل بوضوح بين **تعليماتنا** و**محتوى الملف**، فلا يخلط النموذج بينهما.

### 3.4 بناء ملف Word من الصفر

لا نحتاج مكتبة ضخمة. ملف Word الأدنى ثلاثة ملفات XML داخل ZIP:

```
[Content_Types].xml   ← أنواع الملفات
_rels/.rels           ← أين المستند الرئيسي
word/document.xml     ← الفقرات: <w:p><w:r><w:t>النص</w:t></w:r></w:p>
```

وللعربية نضيف `<w:bidi/>` (اتجاه الفقرة من اليمين) و`<w:rtl/>` (اتجاه النص). ونهرّب الرموز الخاصة (`&` و`<`) حتى لا يتلف الملف.

> **تمرين:** أضف خيار «عرض الأصل والترجمة جنباً إلى جنب» بجدول من عمودين.

## 4. جامعتي: من 10 آلاف جامعة إلى مواد تخصصك فقط

**الملفات:** `src/73-uni.js` و`tools/build_unis.py` و`tools/fetch_aau.py` و`data/`

### 4.1 ثلاث طبقات بيانات، من الأوثق إلى الأقل

| الطبقة | المصدر | الثقة |
|---|---|---|
| **1. خطط موثّقة** | جمعناها آلياً من الموقع الرسمي للجامعة | ✓ رسمية، مع رابط المصدر وتاريخ التحديث |
| **2. بحث بالذكاء الاصطناعي** | Claude يبحث في موقع الجامعة الرسمي فقط | مستخرجة آلياً، مع المصادر ليتحقق الطالب |
| **3. إدخال يدوي** | الطالب يلصق خطته أو يرفع ملفها | من الطالب نفسه |

**لماذا لا نضع «كل مواد كل الجامعات» مباشرة؟** لأن هذه البيانات **غير موجودة في أي قاعدة بيانات مفتوحة في العالم**، وكل جامعة تنشرها بشكل مختلف. اختلاقها خطأ أخلاقي وعملي. الحل الهندسي الصحيح هو الطبقات أعلاه.

### 4.2 قائمة الجامعات: بيانات مفتوحة

استخدمنا قاعدة **Hipo University Domains** (رخصة MIT، تسمح بالاستخدام مع ذكر المصدر): أكثر من 10 آلاف جامعة في 200 دولة. السكربت `tools/build_unis.py` يقسمها **ملفاً لكل دولة**:

```
data/unis/index.json   [["JO",29],["SA",63],...]
data/unis/JO.json      [["Al-Ahliyya Amman University","ammanu.edu.jo"],...]
```

**لماذا ملف لكل دولة؟** الحجم الكلي 1.2 ميغابايت. لو حمّلناه كله لتأخر الموقع على الجوال. هكذا لا يُحمَّل إلا ملف دولتك (بضعة كيلوبايتات). هذا اسمه **التحميل الكسول (lazy loading)**.

### 4.3 جمع الخطط الرسمية: Web Scraping باحترافية

السكربت `tools/fetch_aau.py` يجمع خطط جامعة عمّان الأهلية من موقعها الرسمي:

1. يقرأ صفحة البرامج، فيجد 53 برنامجاً.
2. يفتح صفحة كل برنامج ويجد رابط «الخطة الدراسية».
3. يقرأ الخطة بالإنجليزية **وبالعربية** ويطابق المواد بالرمز.
4. يكتب ملف JSON واحداً مضغوطاً.

```python
for el in page.find_all(["h1", "table"]):          # BeautifulSoup: نمشي على العناوين والجداول بالترتيب
    if "sectiontitle" in el.get("class", []):        # عنوان مجموعة: "Major Requirement - 57 Credit Hours"
        ...
    elif el.name == "table":                         # جدول المواد: الرمز، الاسم، الساعات، المتطلب السابق
        for tr in el.find_all("tr"):
            cells = {td.get("data-label"): clean(td.get_text()) for td in tr.find_all("td")}
```

**أخلاقيات الـ scraping (مهمة جداً في سوق العمل):**
- قرأنا `robots.txt` للموقع أولاً (لا يمنع شيئاً).
- **تأخير 0.6 ثانية** بين الطلبات حتى لا نثقل خادم الجامعة.
- **كاش على القرص** (`.cache/`): لا نعيد تنزيل صفحة نزّلناها.
- **إعادة المحاولة** عند انقطاع الاتصال، و**تخطي** الصفحة المتعثرة بدل توقف كل شيء (حدث فعلاً مع خطة الصيدلة: خادم الجامعة بطيء).
- **User-Agent عام** لا يحمل بيانات شخصية.

**تصميم البيانات:** متطلبات الجامعة (17 مادة) تتكرر في كل التخصصات. بدل تكرارها 53 مرة، نحفظ قاموساً واحداً للمواد `courses: {"03007101": {en, ar, cr}}`، والتخصصات تحمل **الرموز فقط**. هذا **تطبيع البيانات (normalization)** نفسه الذي تتعلمه في مادة قواعد البيانات.

**المتطلبات السابقة:** الموقع يكتبها بالاسم ("Introduction to Programming")، فنحوّلها إلى رموز بقاموس `اسم ← رمز` داخل الخطة نفسها.

### 4.4 طبقة الذكاء الاصطناعي: بحث مقيّد بموقع الجامعة

للجامعات التي لا نملك خطتها، نستخدم **أداة البحث على الويب** في Claude. تعمل على خوادم Anthropic، ونقيّدها **بنطاق الجامعة فقط**:

```js
var tool={type:"web_search_20260209", name:"web_search", max_uses:8, allowed_domains:[u.dom]};
```

- `allowed_domains`: لا يقرأ إلا موقع الجامعة الرسمي، فلا يأخذ معلومات من منتديات أو مواقع غير موثوقة.
- **`pause_turn`**: إذا احتاج البحث وقتاً طويلاً، يتوقف الخادم مؤقتاً ويعيد `stop_reason: "pause_turn"`، فنعيد إرسال المحادثة كما هي ليكمل:

```js
if(msg.stop_reason==="pause_turn" && rounds++<4){ msgs.push({role:"assistant", content:msg.content}); return step() }
```

- **المصادر:** نجمع روابط نتائج البحث والاقتباسات (citations) ونعرضها للطالب. **الشفافية تبني الثقة.**
- **التحقق من مخرجات النموذج:** لا نثق بأي JSON يأتي من النموذج كما هو. الدالتان `str()` و`num()` تقصّان النصوص الطويلة وترفضان الأرقام غير المنطقية (ساعات أكثر من 30 لمادة واحدة مثلاً)، و`safeUrl()` لا تقبل إلا روابط `https`.

> **جرّب بنفسك:** اختر جامعة غير موثّقة، واضغط «ابحث في موقع الجامعة»، وافتح المصادر لتقارن.
>
> **تمرين (مستوى متقدم):** اكتب `tools/fetch_ju.py` لجامعة أخرى. افتح موقعها، وافحص HTML صفحة الخطة (F12 ← Elements)، وعدّل دالة `parse_plan`. أي جامعة تضيفها تصبح «موثّقة» لكل طلابها.

## 5. طريقك إلى التخرج: الخوارزمية

**الملف:** `src/73-uni.js` (الدوال `planStats` و`available`)

### 5.1 حساب الساعات المنجزة بدقة

ليست مجرد جمع ساعات المواد الناجحة، لأن:
- **المواد الاختيارية لها سقف:** «اختر 9 ساعات من 27». إذا نجحت في 12 ساعة اختيارية، يُحسب 9 فقط.
- **المواد الاستدراكية لا تُحسب** في ساعات التخرج (الخطة الرسمية تقول 132 ساعة، بينما مجموع كل الجداول 141 لأن فيها 9 ساعات استدراكية).

```js
var req=g.h||all;                                            // الساعات المطلوبة من هذه المجموعة
var done=Math.min(req, ساعات المواد الناجحة في المجموعة);    // لا نتجاوز السقف
```

### 5.2 «متاحة لك في الفصل القادم»: رسم بياني للمتطلبات

المواد ومتطلباتها السابقة تشكّل **رسماً بيانياً موجّهاً (Directed Acyclic Graph)**: «البرمجة 1» ← «البرمجة الكائنية» ← «هياكل البيانات» ← «الخوارزميات». المادة **متاحة** إذا:
1. لم تأخذها بعد.
2. نجحت في **كل** متطلباتها السابقة.
3. ليست في مجموعة اختيارية أكملت ساعاتها.

### 5.3 اقتراح جدول الفصل: خوارزمية جشعة (Greedy)

نرتّب المتاحة: الإجباري قبل الاختياري، ثم حسب **مستوى المادة** (الرقم الأول من آخر ثلاثة أرقام في الرمز: `03007301` ← المستوى 3)، ثم نملأ الجدول حتى تصل إلى عدد ساعاتك في الفصل (15 افتراضياً). هذه **خوارزمية جشعة**: تختار الأفضل في كل خطوة. ليست مثالية دائماً، لكنها سريعة ومفهومة. ولهذا نذكّر الطالب بمراجعة مرشده الأكاديمي.

> **تمرين (مادة الخوارزميات):** احسب **أقصر مدة ممكنة للتخرج** مع قيود المتطلبات وحد الساعات في الفصل. هذه مسألة **جدولة مع قيود** (scheduling with precedence constraints)، وحلّها بالترتيب الطوبولوجي (topological sort) مشروع تخرج ممتاز.

## 6. الأمان: كيف نحمي الطالب

| الخطر | الحماية في يونس |
|---|---|
| **XSS** (حقن كود في الصفحة) | كل نص من المستخدم أو الملفات أو الذكاء الاصطناعي يمر بدالة `esc()` قبل عرضه. `renderMd()` **تهرّب النص أولاً** ثم تضيف التنسيق، فلا يمكن أن يصبح أي محتوى كوداً. |
| **روابط خبيثة** | `safeUrl()` لا تقبل إلا `https://`، ونضيف `rel="noopener noreferrer"` لكل رابط خارجي. |
| **سكربتات خارجية** | سياسة CSP صارمة: `script-src 'self'`، فلا يعمل أي سكربت من خارج الموقع، ولا `eval`. والاتصال مسموح فقط بالموقع نفسه وبـ `api.anthropic.com`. |
| **حقن التعليمات (prompt injection)** | صفحة جامعة قد تحتوي نصاً يحاول توجيه النموذج. لكن مخرجات النموذج تُعرض كبيانات مُهرَّبة فقط، ولا تنفّذ أي إجراء، ونوسمها «تحقّق منه» مع المصادر. |
| **الخصوصية** | الصور والملفات تبقى في ذاكرة الصفحة فقط، ولا تُحفظ في `localStorage`، ولا تُرسل إلا حين يضغط الطالب «حلّل» أو «ترجم». والكاميرا تتوقف فور مغادرة الصفحة. |
| **استهلاك الموارد** | حدود واضحة: 5 صور، و25 ميغابايت للملف، و40 صفحة مصوّرة، و200 ألف حرف للترجمة، و300 مادة للخطة. |
| **المفتاح** | يبقى في متصفح الطالب، ولا يدخل النسخة الاحتياطية (يتحقق اختبار آلي من ذلك). |

**قاعدة ذهبية:** لا تثق بأي مدخل، سواء من المستخدم أو من ملف أو من موقع أو من نموذج ذكاء اصطناعي.

## 7. الاختبار الآلي

**الملف:** `tests/e2e.js` (Playwright)

الاختبار الآلي يفتح الموقع في متصفح حقيقي ويستخدمه كطالب: يضغط ويكتب ويرفع ملفات، ثم يتحقق من النتيجة. أهم فكرة: **محاكاة Claude (mocking)**. نعترض كل طلب إلى `api.anthropic.com` ونرد بإجابة جاهزة بصيغة البث نفسها (SSE)، فنختبر بلا تكلفة وبنتائج ثابتة:

```js
await ctx.route('https://api.anthropic.com/**', async route => {
  const body = JSON.parse(route.request().postData());
  // نتحقق مما أرسله الموقع فعلاً: هل فيه صورة JPEG؟ هل البحث مقيّد بنطاق الجامعة؟
  await route.fulfill({ status: 200, headers: {'content-type':'text/event-stream'}, body: sse('الجواب النهائي: 42') });
});
```

**أمثلة من الاختبارات الجديدة:**
- رفع صورة حقيقية 2880×1800 والتحقق من أنها صُغّرت إلى أقل من 2576 بكسل و3.75 ميغابكسل.
- التحقق من أن الطلب يحمل صورة JPEG بصيغة base64 وتعليمات نظام و`effort: high`.
- نص طويل يُترجم على 3 أجزاء بالترتيب، وملف Word المنزّل ملف ZIP حقيقي (يبدأ بـ `PK`).
- النجاح في «مقدمة في تكنولوجيا المعلومات» يضيف 3 ساعات، ويجعل «مقدمة في البرمجة» متاحة.
- البحث بالذكاء الاصطناعي مقيّد بنطاق الجامعة، والروابط `https` مع `noopener`.
- لا أخطاء في الصفحة، ولا مخالفات CSP، ولا تمرير أفقي على شاشة 375 بكسل، ولا مشكلات وصول خطيرة (axe).
